# AgentNext 纯 GUI 内部 Beta：目标与交付约定

日期：2026-10-20。状态：**方向已确认，实施与验收进行中；本文不是完成报告。**

本文件落实已确认的选择：可靠的通用内部 Beta；正式验收全部通过 GUI；默认日常执行也只走 GUI。当前实现状态见 [README](../README.md)，权威边界见 [决策记录 D11](decisions.md#d11-纯-gui-内部-beta)。

## 产品结果与范围

用户提出自然语言任务，经必要澄清和计划审阅，agent 在私有 display 中操作单个或多个 App。执行中检查效果，遇到常见失败采取有界恢复，遇到承诺或身份验证请求确认/接管，最终交付可核验结果与未完成项。

- Android 13/API 33 起，Android 13 手机与 Android 16 设备分别验收；单用户、单任务串行执行。
- 业务操作使用界面观察、截图、控件定位、点击、`setText`、滚动、返回和切换 App。
- 允许基础设施查询与 App 启动；禁止 CalendarContract、MediaStore、AlarmClock、私有业务接口或业务 deep link 直接完成业务写入。
- 外部测试 oracle 可以查询真实结果，但不能把查询结果提供给运行中的 agent。
- GUI skill 可选，无专用 skill 的通用路径须独立验收。
- 不包含 iOS、同机多 agent 并发、后台定时任务、社区 skill 上线、跨设备记忆同步或公开商店发布。

## 目标架构与接口

保持 `app → brain → device-api ← capability`。目标链路为任务理解 → 计划 → GUI 策略 → 受信任定位 → 统一执行 → 效果/进展判断 → 恢复 → 最终核验。

以下是**拟新增或调整的接口契约**，不能假定同名类型已在当前代码实现。

| 接口 / 类型 | 职责 |
|---|---|
| `TaskContract` | 保存目标、结构化参数、必需结果、禁止事项、允许 App 和版本；skill 不得削弱 |
| `PlanValidator` | 初始规划与重规划共用，校验要求覆盖、DAG、App、verifier 和预算 |
| `ActionProposal` | 策略只提供语义动作、目标、参数和预期效果，不携带设备权限或执行回调 |
| `GroundedAction` | 受信任定位结果，绑定 task、target、观察版本和证据；坐标仅在受信任层使用 |
| `ActionExecutor` | 唯一副作用入口，统一取消、校验、风险、确认、执行、回执和审计 |
| `VerificationResult` | 按条件 ID 返回 `SATISFIED / UNSATISFIED / UNKNOWN` 和来源、时间、观察版本 |
| `TaskReport` | 最终状态、满足/未满足条件、结果内容、介入、失败与统计 |
| `ExecutionContext` | 向模型、观察、等待、输入传递取消信号、截止时间、版本与预算 |

关键约束：

- 准备页面、返回、候选重试和组合技能内部输入均经过统一执行器。
- 根据实际目标与上下文独立分类风险，模型的 LOW 不能降低风险判定。
- A3 承诺逐次确认；任务禁止事项不能通过普通确认解除；凭据、OTP、验证码和生物识别交人处理。
- 确认绑定具体 payload、目标、task 版本和一次性 action ID；重启、内容或上下文变化后失效。
- 暂停或接管后丢弃未执行 proposal，重新观察；已提交但结果未知的动作先核验，不重放。
- 必需结果全部验证才能 `DONE`；部分完成返回 `PARTIAL`，等待用户返回 `NEED_USER`，停止与失败独立表达。

## M0–M6 实施路线

按顺序实施，每阶段单独验证和提交。下表均为交付要求；完成状态必须链接具体测试报告。

| 阶段 | 实施内容 | 出口条件 |
|---|---|---|
| M0 工程基线 | 修 host stub；建立缺陷回归和统一验证入口；smoke 仅 debug；清理环境路径和文档状态 | 构建/回归可重复，release 无自动诊断入口 |
| M1 动作治理 | 唯一执行器、独立风险分类、一次性确认、组合动作逐步取消、用户/agent 输入互斥 | LOW 支付不放行；停止不执行后续步骤；无并发输入 |
| M2 任务与证据 | 结构化参数、要求覆盖、禁止整份计划被 skill 替换、严格 verifier、任务级最终核验 | 不丢要求、不误报完成、中文/跨午夜/缺参处理正确 |
| M3 有界恢复 | 区分变化与进展、稳定观察、重定位/返回/重规划、分离尝试和重试、下游数据检查 | 长步骤不误停，循环有界，副作用不重复 |
| M4 纯 GUI 通用路径 | 直接业务写入退出 runtime；动态 App 发现；统一控件/视觉定位；通用 GUI skill | 日历/文件/计算器重新纯 GUI 验收，无专用 skill 仍可运行 |
| M5 生命周期 | Service 持有任务、状态快照、任务隔离、加密检查点、取消贯通、接管与结果 UI | 重建可恢复、重启不重放、清除级联、恢复使用新观察 |
| M6 评测与发布 | 固定任务/保留集、外部 oracle、故障套件、双设备兼容、真实并发、内部签名分发 | 满足全部发布门槛 |

### 参数、恢复与预算默认值（待实施）

- 自然语言解析为结构化参数后校验并确认；时间基准为任务开始时的设备日期/时区，执行与验证不重复解释原始文本。
- 缺少关键参数须澄清，不静默回退到 09:00、07:00 或 `agent-demo`；支持中文名称与跨午夜。
- 任务最多 80 次实际 GUI 输入、20 分钟主动执行、120 次模型请求；网络重试计入请求数。
- 每子目标初次执行加两次重试，全任务最多三次重规划；成功子目标不占重试次数。
- 初始计划最多八节点，插入修复后最多十二节点。
- 用户等待不占主动执行计时，单次最长十五分钟。
- 稳定观察采用两次间隔 250ms 的兼容状态采样；普通等待最多三秒，加载最多十秒，然后进入恢复。
- 视觉定位候选置信度默认至少 0.85，前两候选差至少 0.15；不满足则获取其他证据或交人。置信度不替代风险判断。
- 恢复顺序：重新观察 → 等待 → 安全重定位 → 可验证返回/换路径 → 受约束重规划 → 询问用户。
- 预算不随重试重置；耗尽时报告部分结果。模型不得扩大 App/权限范围或删除必需结果。

### 生命周期与隐私交付要求

以下待实施部分不能视为当前保护保证：

- Service 持有会话，Activity 订阅即获得快照；停止两秒内关闭新动作派发，在途调用与收尾单独记录。
- 每任务独立 WorkingMemory，阶段输出整体替换；必需下游数据缺失时不得继续。
- 加密检查点记录合同、图、证据摘要、预算和动作提交状态；关键记录失败时不执行副作用。
- 重启后等待用户恢复，重新观察并核验在途动作；旧确认失效。
- 凭据接管时暂停采集和模型请求、隐藏预览；主屏接管先由用户确认，主屏禁止 agent 输入。
- 事件保留三十天、暂停检查点二十四小时；完成/停止清理任务内存与检查点；清除级联。
- 默认不持久化截图和完整 UI 树；日志不记录输入正文、完整屏幕文本和模型原始返回。

## 测试集合与发布门槛

开发集 24 个任务，每组四个：

| 组 | 任务范围 |
|---|---|
| 日历 | 指定时间创建、中文标题、跨午夜、重开核验提醒 |
| 文件 | 中文目录、定位测试文件、复制到目录、重命名与重开核验 |
| 计算器 | 整数、小数表达式、清除旧结果再计算、最终显示核验 |
| 浏览器 | 搜索、页内查找、读取指定事实、带来源比较摘要 |
| JD | 搜索、筛选、匹配规格加购、重开购物车核验；不结算 |
| 跨 App | 天气条件→日历、计算→笔记、网页→笔记、文件信息→笔记 |

通用保留集 12 个任务：备忘录、时钟、联系人各四个。关闭对应 App 专用 profile/policy/workflow，仅使用通用能力。开发前冻结具体任务、参数与 oracle；用于针对性修复后，该保留集转为开发数据，补充新的冻结保留集再评测。

发布必须满足：

1. 两台设备各三轮完整测试，分别统计；每台设备开发集自主完成率 ≥80%，保留集 ≥60%。
2. 误报 `DONE`、未经确认的承诺操作、停止后新派发输入均为零；任一次发生即阻断候选版本。
3. 固定故障套件符合预期；真实二十分钟 agent 运行与用户主屏使用并发通过，而非只测 Service 存活。
4. 干净状态启动；原已存在结果单独标注，不计入创建类任务的自主完成。人工辅助、合理停止和普通失败单列。
5. 记录代码/模型/App/设备版本、初始状态、耗时、模型调用、实际输入、重试、重规划与接管；环境/账号/风控失败不得事后剔除。
6. 真实支付、下单、外发和不可逆删除在合成 App 验证；测试使用专用数据和设备。

固定回归包括：LOW 提交、确认重放、注入文本、多要求覆盖、中文与跨午夜、旧结果/错误对象、UNKNOWN 核验、长步骤/八段计划、弹窗/加载/循环、断网/429、目标或服务退出、取消/接管/进程回收、跨任务数据隔离、加密存储故障和 GUI 路径审计。

零事故仅表示通过该测试集，不表示任意 App 安全保证。构建、host 或历史 smoke 通过不替代完整设备验收。

## 迁移与文档约定

- 直接写入 skill 退出产品注册，保留历史实现与证据；不将旧接口路径的 PASS 迁入纯 GUI 成绩。
- 保留模型配置兼容性；新检查点带版本，未知版本不恢复执行。
- 不引入新运行时框架；沿用 JVM host 测试与 testkit，设备测试负责 Android 行为。
- 正确性稳定后再减少重复视觉调用；核验缓存不得跨任务、接管或目标切换复用。
- 发布前检查签名、manifest、权限、版本和校验和；仅内部测试设备分发，附安装/模型配置/Shizuku/接管说明。
- [0.1 发布记录](beta-release-notes.md) 和日期 smoke 是历史证据；本文件是目标，不能作为发布完成证明。
