# 手机 Agent 任务测试集 v2（基于用户需求调研）

日期：2026-10-20  
设备：Redmi Pad Pro / Android 16  
上一版问题：10 条里有 7 条都是“建日程”，只测了一个能力面。  
本版原则：**每条任务解决一个不同的用户目的**；优先覆盖真实用户会交给手机 agent 的工作，而不是容易自动化的单一日历写入。

## 一、调研结论：人到底想让手机 Agent 做什么

### 1. 通用 Agent：生产力与学习是主需求

Perplexity 与哈佛研究者对 Comet 浏览器/助手数亿次查询的分析（IndexBox/Euronews 报道）显示：

- **36%** 的任务是生产力与工作流：写文档、过滤邮件、总结信息、创建日历等；
- **21%** 是学习与研究：总结课程材料、查资料；
- 其余高频包括购物、旅行、求职；
- **55%** 与个人生活相关，30% 与工作相关，16% 与教育相关；
- 用户会从简单的旅行/媒体任务，逐渐转向生产力、学习和职业类任务。

来源：[IndexBox 报道](https://www.indexbox.io/blog/2025-study-millions-use-ai-agents-for-learning-and-productivity/)、[Euronews](https://www.euronews.com/2025/12/10/most-people-use-ai-agents-for-productivity-and-learning-perplexity-says)

PYMNTS 也把“日常规划与购物”列为本轮消费者转向 AI 助手的主要拉动场景：[PYMNTS](https://www.pymnts.com/news/artificial-intelligence/2025/everyday-planning-and-shopping-lead-consumer-shift-to-ai-assistants/)

### 2. 豆包手机：用户实际在做什么

钛媒体对二代豆包手机的评测和扬子晚报对首发的报道里，出现频率最高的真实用法是：

- 抖音内点赞、评论、自动刷视频、批量收藏；
- 飞书群消息总结、看待办、转发文档、会议纪要；
- 跨 App 出差规划：飞书日程 + 携程机票酒店 + 百度地图通勤；
- 多任务并行：抖音找视频、去哪儿搜机票、瑞幸点咖啡；
- 京东/抖音商城比价、加购物车；
- 系统设置：22:00 自动深色模式、静音；
- 相册/录音检索：查港澳通行证有效期、从录音里找电话号码；
- 招聘 App 自动搜岗位、发招呼语，10 分钟投 30 份简历；
- 文件打包、分类、压缩后发给同事。

同时，豆包手机明确暴露了边界：微信、淘宝、美团等高频 App 风控/未授权；支付、实名认证要人工；视频剪辑等多素材任务不稳定；单步 2–3 秒，比人慢。

来源：[钛媒体：二代豆包手机值得买吗](https://www.tmtpost.com/8149111.html)、[新浪：豆包手机上线5日](https://k.sina.com.cn/article_1653603955_628ffe7302001tt4k.html)

### 3. Meta Muse：用户要的是“跑腿 + 知识工作”

Muse 的公开能力包括：发邮件、查资料、订餐厅/旅行、填表、安排日程、设定目标并拆解计划、后台持续跟踪（学校邮件、家庭日程、购物清单、截止日期），复杂电话任务还有人工 concierge 兜底。

来源：[VTV 报道](https://vtv.vn/meta-trinh-lang-tro-ly-ca-nhan-muse-biet-gui-email-dat-phong-nhac-nho-lich-trinh-xay-dung-ke-hoach-100260910084238419.htm)、[CNA/Reuters](https://www.channelnewsasia.com/business/exclusive-meta-testing-human-concierge-its-new-personal-ai-agent-muse-6402946)

### 4. Grok Bot：云端电脑型 Agent，偏“研究与执行”

Grok Bot 的官方使用指南里，典型任务是：Costco/Amazon 加购并比较价格、配送费和时效；把 X 关注者整理成 Notion CRM；搭建健身教练 bot；给 Cursor 写外层提示词；跨 Slack/Notion/GitHub 找答案；监控 Facebook Marketplace。它更像“有电脑的同事”，不是手机上的点按助手。

来源：[x.ai Grok Bot 101](https://x.ai/bot/guides/grok-bot-101)

### 5. 学术 benchmark 的任务分类

- **SPA-Bench**：340 个任务，覆盖系统 App 与第三方 App、中英文、单 App 与跨 App；跨 App 类型包括 General Tool、Information Management、Web Shopping、Media Entertainment、Social Sharing、Multi-Apps。
- **iOSWorld**：133 个任务，27 个单 App、60 个多 App、46 个记忆/个性化；最佳配置整体 52%，多 App 只有 37%。说明“跨 App + 个人记忆”是价值最高也最难的部分。

来源：[SPA-Bench](https://ar5iv.labs.arxiv.org/html/2410.15164)、[iOSWorld](https://huggingface.co/papers/2606.09764)

## 二、需求归纳

把以上信息合并，手机 agent 的高频目的可以归为 8 类：

1. **研究后做决定**：查资料、比价、看天气/航班，输出结论；
2. **购物与消费**：搜索、比价、加购、下单（下单需人确认）；
3. **出行与本地生活**：机票/酒店/高铁、餐厅、路线、打车；
4. **生产力**：文档、邮件、会议纪要、待办；
5. **个人记忆与清单**：笔记、购物清单、偏好、证件/录音检索；
6. **时间与设备自动化**：闹钟、深色模式、静音、定时任务；
7. **文件与内容整理**：下载目录、分类、压缩、发送；
8. **沟通草稿**：邮件/消息草稿，发送必须人工确认。

上一版只覆盖了第 5 类里的“日历”，所以测试集必须换。

### 为什么是这 10 条

- 1、3 是“研究 + 跨 App 产出”，对应 Perplexity 的 21% 学习/研究和豆包手机的出差规划；
- 2 对应豆包/Grok Bot 的比价加购，以及 SPA-Bench 的 Web Shopping；
- 4、8 对应 36% 的生产力/工作流（文档、邮件）；
- 5、10 对应 iOSWorld 的“个人身份/记忆”和日常 PIM；
- 6、7 对应 SPA-Bench 的系统 App 与文件整理，以及豆包手机的文件打包；
- 9 是纯工具型任务，验证视觉/控件混合点击，不涉及外部副作用。

## 四、每条的执行设计与边界

### 1. 天气 → 带伞结论

- 路径：Quark 搜索“上海明天天气” → 读取降雨信息 → 备忘录新建“明天带伞”；
- 验证：Quark 结果帧 matched 条件 + Notes 文本；
- 风险：Quark 视觉 verifier 历史上有波动；不涉及支付/登录。

### 2. 京东比价加购

- 路径：京东搜索“机械键盘” → 结果页读取前 3 个价格 → 加购最低价；
- 验证：购物车数量、商品标题/价格；**不结算**；
- 风险：京东详情页无障碍树为空、购物车 tab 视觉定位不稳；需要人工兜底。

### 3. 高铁查询 → 备忘录

- 路径：Quark 搜索“上海到北京 明天 高铁” → 选择 9 点前车次 → 记录车次/时间到备忘录；
- 验证：备忘录含车次号和时间；**不订票**；
- 风险：网页结果结构化提取、车次信息可能因日期变化；不涉及 12306 账号/支付。

### 4. WPS 周报

- 路径：WPS 新建文档 → 输入标题/三条进展 → 保存到 Documents；
- 验证：`/sdcard/Documents/` 下文件存在，重新打开文本一致；
- 风险：WPS 首次启动引导/登录；只写本地文件。

### 5. 备忘录购物清单

- 路径：备忘录新建 → 标题“购物清单” → 三条条目 → 勾选牛奶；
- 验证：重新打开笔记，文本/勾选状态一致；
- 风险：MIUI Notes provider 未导出，需要 UI domain 或 intent。

### 6. 闹钟

- 路径：Clock 设置工作日 7:30；
- 验证：Clock 列表/下一个闹钟；
- 风险：当前 verifier 只看 `getNextAlarmClock()`，多闹钟会误判；需要枚举全部闹钟。

### 7. 文件整理

- 路径：Download 建 `apk` → 把 `agent-next-debug.apk` 移入；
- 验证：`/sdcard/Download/apk/agent-next-debug.apk` 存在，原路径不存在；
- 风险：文件管理器 UI 的“浏览”节点不可点击；需要 MediaStore/文件 domain 的 move。

### 8. 邮件草稿

- 路径：邮件 App 新建 → 收件人/主题/正文 → 保存草稿；**不点发送**；
- 验证：草稿箱出现该主题；已发送为空；
- 风险：邮件账号可能未配置；发送是外部副作用，必须 RiskGate 拦截。

### 9. 计算器

- 路径：视觉/控件混合定位按键 → 输入 1234×5678 → 等号 → 校验 7006652；
- 验证：显示区文本；
- 风险：已知纯视觉在 720×1280 小键盘上会误选显示区；需 hybrid + 冷启动等待。

### 10. 联系人

- 路径：联系人新建 → 姓名/手机号/备注 → 保存；
- 验证：ContactsContract 查询到该姓名/号码；
- 风险：READ/WRITE_CONTACTS 运行时授权；只写本地联系人。

## 五、暂不纳入的高价值/高风险场景

这些是调研中出现、但当前不适合放进“可确认 green suite”的：

| 场景 | 为什么不纳入 |
|---|---|
| 微信/短信代回复 | 平台风控、外部发送不可逆；必须人工确认，且当前设备无账号 |
| 外卖/咖啡/打车下单 | 需要支付/地址/账号；外部副作用，失败成本高 |
| 投简历 | 外部可见、不可撤回；需要岗位 App 账号；应做“草稿+人工确认” |
| 抖音自动刷/点赞/收藏 | 账号互动和平台激励风险；豆包已因此下线部分能力 |
| 机票/酒店预订 | 支付和退改风险；只做“查+记”，不做“订” |
| 相册证件/录音检索 | 高隐私；需要本地 OCR/ASR 和明确授权，当前不做 |

## 六、建议的补齐顺序

按“覆盖目的数 / 实现成本”排序：

1. **Notes domain**（覆盖 1、3、5 三条，且是跨 App 输出的落点）；
2. **Files move/rename**（覆盖 7，且比 UI 点击稳）；
3. **Contacts domain**（覆盖 10，权限模型清晰）；
4. **WPS 文档 domain**（覆盖 4，生产力主场景）；
5. **Mail 草稿 domain**（覆盖 8，必须强制“不发送”）；
6. **Clock 全量闹钟校验**（覆盖 6，修 verifier）；
7. **Quark 结果结构化提取**（覆盖 1、3，提升跨 App 成功率）；
8. **Calculator 冷启动 + hybrid**（覆盖 9，作为视觉/控件测试床）。

完成 1–4 后，这套 10 条里可以有 7 条进入可重复 green suite；5–8 再补齐邮件、闹钟、研究和计算。
