## 任务与操作规则

测试原文：“在夸克搜索西红柿炒鸡蛋的做法，打开一篇相关内容，停留在正文并告诉我标题。不要登录、发送或购买。”

业务任务由通用模型依据实时界面选择语义动作。电脑只读监看，不替 Agent 操作浏览器，不注入搜索词，不使用固定点击序列。测试人员只在 AgentNext 自己的任务页生成并确认计划，然后返回主屏。最终必须同时检查内容页、主题、标题和正文，不能把搜索建议或结果页当作已打开正文。

## 启动方法

1. 安装与源码一致的 Debug APK，先启动并授权 Shizuku，在“设置与隐私”导入 HTTPS 模型配置。
2. Android 开启无线调试，电脑与设备连同一网络。已配对设备执行 `adb connect DEVICE_IP:DEBUG_PORT`；未配对时先按系统“使用配对码配对设备”提供的地址和端口执行 `adb pair`，由本人输入配对码。连接端口与配对端口不同，每次重启可能变化。
3. 打开 AgentNext，选择夸克，勾选“电脑只读监看”，输入上述自然语言任务，生成并审阅计划后确认执行。
4. 电脑运行：

```sh
python3 tools/demo-viewer.py --adb /path/to/adb --serial DEVICE_IP:DEBUG_PORT
```

打开 `http://127.0.0.1:8765/`。查看器只读固定的 app 私有缓存；无控制接口。首次出图前显示等待；帧超过五秒、ADB 断开或任务结束时明确标记，旧帧不能称为实时。

本轮终态查看曾出现一次 ADB 读帧超时，随后读取恢复，设备仍在线；查看器保留了“过期最后画面”的明确提示。录制前应检查无线链路，静止正文的最后帧和超时保留帧都不能当成持续直播证明。

5. 用户返回主屏，持续滚动和中文输入；任务运行时同时录下主屏与电脑后台画面。交互“预览/接管”会暂停 Agent，不能用它代替后台监看。后台执行与电脑只读监看时目标 App 保持静音，只有用户主动接管（交互预览或主屏接管）才恢复声音；不能用“有没有声音”判断 Agent 是否在真实执行，验收看画面、帧序号与最终结果。
6. 核对最终 App 页面与报告。失败、验证码、网络异常或证据不足均记录原状；不要改任务定义来宣布成功。

设备已有安装包时，覆盖更新必须使用相同签名。遇到签名不一致先处理本地签名，不能卸载清数据来掩盖问题；私有签名和模型配置不提交。音频隔离依赖 Shizuku shell 权限；若设备拒绝音频策略，任务会阻止目标启动并报错，此时按失败记录，不要为了演示关闭隔离或改用全局静音。

## 已落实的工程收敛

- 连接检查不再重置健康连接，连接请求不会被在途检查吞掉；单一连接所有者，避免替换监听器。
- 实机发现终态过早停止前台服务会触发后台进程冻结，延后了最后一帧和资源清理；唤醒应用后立即完成。修复为清理与镜像发布完成后才停止服务，第四轮已观察到后台终态自动active=false。
- 运行状态和服务通知由 runtime 更新，Activity 离开后继续执行；计划开始清理旧计划，停止可贯通规划边界。完整进程恢复仍未实现。
- Debug 只读镜像与人工接管分开，只有最新帧；帧发布不再丢弃短时间内的最终更新，发布代际隔离，结束时刷新最后画面。
- 实际命中控件的语义参与风险判断；再次定位时校验任务、目标与节点指纹，降低中性动作描述绕过支付限制和节点替换风险。
- 修复过程提示误用120字输入上限的问题，完整阶段、约束和终态条件进入模型请求；节点摘要和输入文字上限不变。
- 浏览器搜索/打开/标题任务在确认前归一化为一个最终目标，完整保留原始任务与权限，由模型自主决定输入、提交、打开等动作。中间搜索页不再作为最终仍需存在的状态；其他任务不改变。该路径绕过旧固定天气策略。
- 归一化只接受限定的只读任务表达；存在收藏、下载、分享等额外指令或无法识别的表述时，保守保留原计划。搜索主题中的指令连接词也会退出此特殊路径；这可能拒绝部分正常主题，是当前刻意收窄的兼容性限制，不是通用自然语言解析。
- 新增显式 WebTextContains：只接受稳定完整观察中的唯一可见文本、真实WebView祖先与完整边界，未接受模型坐标。它不证明文本必然是链接，仍须后续观察及最终结果核验。
- 模型看到每个节点由执行器计算的 webTextEligible；用同一资格判断选择 WebText 类型，仍需在派发前重新观察、唯一匹配及风险校验。
- 产品路径禁用有缺陷的全任务重规划；保留有界局部反馈和明确交接。特定浏览器任务的终态核验保留原始用户目标，每次清除旧证据。

浏览器正文核验成功后，私有页面和轻量前台通知会保留，便于用户检查；点“停止”或开始新任务才释放。失败、部分完成和停止仍自动清理，不能把最后截图当作页面仍存在的证明。第六轮已验证DONE后页面和结果报告仍存在；开始新任务时旧页面正常释放。

这些收敛不等于通用安全或通用任务成功。最终页面仍由视觉模型判断，不能独立证明历史上的每一次搜索操作；其他任务尚未接入相同的原始目标核验。

## AI 辅助编码与审查

本次使用 Codex 辅助定位、编码、回归和只读复核，以“并行不抢屏、真实界面决策、结果有证据”三项约束限制范围。没有让模型为演示生成固定点击序列，也没有用电脑替代 Agent 操作夸克；测试人员只操作 AgentNext 的计划入口和返回主屏。

实机失败推动了修复：连接请求被在途检查吞掉、后台进程在清理前冻结、WebView 标题缺 CLICKABLE、过程提示误被截成120字，以及计划中间条件阻碍最终完成。关键边界先写反例再修复，例如中性描述不能绕过支付控件、旧节点不能复用授权、额外收藏要求不能被只读计划合并丢弃。另做独立只读代码复核，修复反馈后重新构建并按安装包复跑；模块测试与真实任务记录分别呈现。答辩需能解释这些取舍、失败证据和剩余限制。

## 录制安排（目标 90–120 秒）

开始前生成并审阅计划，准备好电脑查看器；使用非敏感演示内容。正式录制用一个连续镜头同时拍到设备主屏与电脑后台画面。

- 0–10 秒：展示原始自然语言任务，由本人点击确认，返回自己正在使用的主屏 App。
- 执行期间：本人持续滚动、中文输入和移动光标；电脑显示真实后台动作、帧序号和状态。不要打开交互预览，以免主动暂停 Agent。
- 完成后：同时展示 DONE 的实际标题和正文页；需要在手机检查时由本人主动打开预览。不要只用状态文字替代执行画面。
- 保留完整原始录像和失败尝试；不要把不同尝试剪成一次成功。若本次超过两分钟，保留长版并重新演练，不以剪辑伪造速度或同时发生。

这是一台平板的实测记录；录制与答辩如实说明设备形态、Shizuku 权限与兼容性范围。仓库访问权限、提交链接与最终视频仍需在正式提交前补齐。
