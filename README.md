## 0. 30 秒看懂

手机从设计上假设「一个人用一块屏」：输入、焦点、键盘都继承了这个假设。AgentNext 要验证的是——**在这台手机的正常使用不被打断的前提下，Agent 能不能在幕后把真实 App 里的任务做完**。

- **做什么**：用户用自然语言下达任务，Agent 根据实时界面逐动作决策，在真实第三方 App（当前验证：夸克）完成多步操作，最后给出可核验结果，或明确停在哪个边界、需要用户做什么。
- **怎么做**：用 Shizuku user service 创建私有虚拟屏 → 把目标 App 的 task 移入该屏 → 只对该屏观察与定向输入 → 目标 App 按 UID 静音。用户的主屏、焦点和输入法完全不受影响。
- **到哪一步**：已完成两条真实任务闭环（浏览器、京东购物）；2026-10-21 录到“用户用键盘输入 + 手写的同时，Agent 在私有屏完成京东搜索→规格→购物车→订单核对页，并在支付边界请求人工接管”的同屏视频；**尚缺打码后的正式视频、Android 13 验收和更广的任务集**，详见对照表。
- **为什么不是别的路线**：见 [§5](#5-为什么选这条路技术取舍)。

## 1. 硬性要求对照

> 要求原文来自题目。状态口径：**满足** = 有可复核的真机证据且覆盖该要求；**部分** = 机制已实现或有单点验证，但覆盖不足。

| 硬性要求 | 状态 | 证据 | 主要缺口 |
|---|---|---|---|
| **是 Agent，而不是一段脚本** | 部分 | 每轮重新观察页面后由模型选择单个动作，动作未命中定位不派发，失败反馈进入下一轮（[实时执行说明](docs/reactive-agent-2026-10-21.md)）；通用弹窗检测/关闭已做真机验证（[记录](docs/popup-handling-2026-10-21.md)）；京东演示中页面由搜索、详情、规格、购物车连续变化到订单页，到达边界后走独立核验与接管，不是固定回放 | 跨主题、跨 App 泛化未证明；部分 domain skill 仍是预置流程 |
| **和用户同时用手机** | 部分 | 私有 display + 定向输入；2026-10-21 京东任务录屏中用户在笔记 App 里键盘输入并手写，Agent 同时在私有屏完成购物流程（[§2](#2-演示与已跑通的任务)） | 录屏待打码/剪辑发布；并发卡顿/焦点抖动未量化；20 分钟 soak 只证明前台服务存活 |
| **Agent 要能操作 App** | 部分 | 夸克 10.19.0.1165 内连续三次完成“搜索 → 打开正文 → 核验标题”；京东完成搜索 → 详情 → 规格 → 购物车 → 订单核对页；京东 adapter smoke 通过 | 仍属单任务/单 App 主题；冻结任务集上的成功率/稳定性未统计；WebView/RN 控件定位仍是弱项 |
| **不打扰用户（主动交接不算打扰）** | 部分 | 设备层把观察/输入限定在私有 display；录屏中用户键盘/焦点未被抢占，目标 App 只出现在用户手动打开的只读预览窗口；目标 App 音频按 UID 静音（[音频隔离记录](docs/device-audio-isolation-2026-10-21.md)）；到达支付边界后以非抢屏通知请求接管（[交接记录](docs/device-handoff-2026-10-21.md)） | 真实支付/登录流程未验证；凭据类动作的主动通知仍缺；并发干扰尚无量化数据 |
| **结果可验证** | 部分 | 完成由独立核验器判定，模型 `Done` 不算成功；失败如实报 `FAILED`/`NEED_USER`；浏览器任务同帧核验标题/主题/正文；购买任务在订单提交/支付边界触发非抢屏接管通知（Agent 不提交订单或付款），录屏停在该通知 | 独立核验覆盖有限；视频未展示 App 结果卡；真实支付/登录边界未验证 |
| **设备权限** | 满足 | 使用无线 ADB + Shizuku，不使用 Root、系统签名或修改 ROM；普通用户落地路径见 [§6](#6-权限与普通用户落地) | 普通用户仍需自行安装 Shizuku，一键化未解决；仅单 ROM 验证 |

## 2. 演示与已跑通的任务

### 2.1 京东购物任务（2026-10-21 录制；视频外部托管）

**任务原文**：“到京东买小米手环11。”

**录屏内容**（设备屏幕录制，1728×1080，128.2 秒）：

- 0–10 秒：在 AgentNext 中确认任务（起始应用：京东 `com.jingdong.app.mall`）并开始，随后切回自己的笔记 App。
- 20–40 秒：用户在笔记里用键盘输入——输入法正常弹出、候选词正常、焦点保持在笔记；左侧只读预览同时显示 Agent 正在私有屏操作京东。
- 50–110 秒：用户继续手写；Agent 完成搜索 → 商品详情 → 规格选择 → 加入购物车 → 购物车 → 去结算 → 订单核对页。
- 124–128 秒：独立核验到订单提交/支付边界后，弹出**非抢屏通知**：“AgentNext 需要人工接管——已核验到订单提交/支付边界，请接管处理；Agent 不会提交订单或付款”，并提供“完成，继续 / 停止”。**Agent 没有点击支付。**

|---|---|
| 录制日期 / 时长 | 2026-10-21 / 128.2 秒 |
| 设备 / 系统 | Redmi Pad Pro（2405CRPFDC）/ Android API 36 |
| 目标 App | 京东（`com.jingdong.app.mall`） |
| 用户前台 | 笔记 App：键盘输入 + 手写，全程持续 |
| Agent 画面 | 私有屏，经用户打开的只读预览窗口实时投射 |
| 结束方式 | 独立核验到支付边界 → 非抢屏通知请求接管；未提交订单、未付款 |
| 演示构建 | Debug APK，SHA-256 `c652008c…`（2026-10-21 11:50 构建；源码 tag `demo-2026-10-21`） |

**演示视频**：视频另行托管，不随仓库分发；仓库只包含源码、文档与证据记录。

## 3. 架构与隔离

```text
用户主屏（继续正常使用，不被打断）
        │
┌───────┴─────────────────────────────────────────────┐
│ Shizuku user service（uid 2000，非 Root）            │
│  私有 virtual display（1080×1920，360 dpi）          │
│    └─ 目标 App task（task move 进入）                │
│  观察：窗口内节点树（≤96 节点）+ 单帧 PNG            │
│  输入：仅对该 display/target 定向注入                │
│  音频：目标 UID → discard sink（仅接管时恢复）       │
└───────┬─────────────────────────────────────────────┘
        │ AIDL
  capability ← device-api ← brain（纯 JVM，不依赖 Android）
        ▲
  app（任务入口 / 前台服务 / 通知 / 预览接管）
```

- **隔离**：目标 App 不在用户主屏出现；`ActivityOptions.setLaunchDisplayId` 启动或 `moveTargetToDisplay` 移入私有屏；观察和输入都绑定 target + window + UID，旧观察、旧句柄、主屏输入一律拒绝——一次观察只授权一个动作。
- **输入法**：私有屏强制 `IME policy HIDE`，不借用全局输入法；非敏感文本用 target-bound `setText`，需要输入法组合/联想时走主屏接管（[D7](docs/decisions.md)）。
- **音频**：后台执行和只读监看时，目标 UID 的播放路由到本地丢弃缓冲，不改全局音量、不静音其他 App；只有用户主动接管才恢复，交还前先确认重新静音；隔离失败会阻止任务启动，而不是降级为有声执行（[D12](docs/decisions.md)）。
- **用户可见性**：前台服务通知 + 轻量状态；用户可随时打开预览查看、接管或停止。

## 4. 执行循环与证据式完成

- **循环**：`observe → 模型选一个动作 → 执行器重新定位并校验 → 回读新页面 → 判断效果`。失败反馈进入下一轮；相同页面上已失败/无效果的相同动作会被拦截；页面变化不等于任务完成。
- **严格接地**：模型只能给语义动作和本轮观察到的节点编号，不能给坐标；执行器在最新观察上唯一命中后，重新观察、重定位并比对节点指纹，才真正落点。
- **风险边界**：支付、下单、发送、删除等承诺动作停在边界交人；密码/OTP/生物识别一律人工；验证码/风控页以不抢屏的通知请求接管（[决策记录](docs/decisions.md)）。**购买类任务在订单提交/支付边界完成独立核验后请求人工接管，不提交订单、不付款**（2.1 的录屏即此流程）。
- **完成**：模型 `Done` 只触发独立核验；核验按完成条件返回满足/不满足/未知，跨 App 结果分别留证；只有所有必需结果通过核验才 `DONE`，否则 `PARTIAL`/`NEED_USER`/`FAILED`，并说明停在哪里。
- **预算**：任务级动作数、时间与模型调用预算封顶；超时、断网、目标退出、停止/接管均按失败或交接处理，不重放未确认的副作用。

## 5. 为什么选这条路（技术取舍）

题目要求“用户正常用手机”和“Agent 同时操作真实 App”。这两条把常见路线分成四种，我们选择了其中门槛与真实性折中的一条：

| 方案 | 同时用手机 | 不打扰 | 普通用户门槛 | 结论 |
|---|---|---|---|---|
| 无障碍服务直接操作主屏（常见 GUI Agent） | 分时共用，本质抢前台 | 差：焦点、输入法、页面都会被切换 | 低 | 不满足“同时用” |
| PC + ADB 远程控制（如 AppAgent 路线） | 手机被独占，Agent 与用户不能并行 | 差 | 需常驻电脑 | 不满足“同时用”，且不是端侧形态 |
| Root / 系统签名 / 改 ROM + 系统 API 直写 | 可以并行 | 取决于实现 | 高：Root、刷机、普通用户难落地 | 题目允许，但无法证明 GUI 能力，且落地成本高；本方案未采用 |
| 第二台手机 / 云手机 / 模拟器 | 可以并行 | 好 | 中：需要第二设备 | 任务不作用于“用户自己的这台手机与账号”，偏离题意（题目允许，但本项目判断不值得） |
| **本方案：Shizuku + 私有虚拟屏** | **是** | **是** | 中：需安装 Shizuku 并做一次无线调试授权 | 在“同一台真实手机”和“普通开发者可得”之间取平衡 |

**为什么坚持纯 GUI**：题目考察的是在真实 App 界面上完成任务的能力。用 CalendarContract、MediaStore、业务私有接口直接写入可以更快完成特定任务，但无法证明界面理解和泛化；因此产品路径全部走 GUI（[D11](docs/decisions.md)），测试工具可以独立核验结果，但不把核验数据喂给执行中的 Agent。

**代价**：依赖 Shizuku、虚拟屏、task move 与按 UID 音频路由，平台/ROM 兼容面窄；可访问性语义在 WebView/RN/自绘控件上覆盖不足。这些代价换来了“同机并行”和“不打扰”，也正是本题最稀缺的部分。

## 6. 权限与普通用户落地

**本项目需要**：
- Android 13（API 33）及以上；
- 一次无线 ADB（用于启动/授权 Shizuku）；
- Shizuku 安装并授权 AgentNext 使用其 user service；
- 通知权限（运行状态与交接）。

**本项目不使用**：Root、系统签名、修改 ROM。因此观察、输入、音频路由全部通过 Shizuku 的 shell 权限完成，不依赖系统特权。

**普通用户如何落地**：安装 Shizuku → 通过无线调试（或电脑 ADB）启动并授权 → 打开 AgentNext 授予 user service。当前仍需手动完成一次授权，**一键化流程尚未解决**，这是本方案的主要门槛，也是 [§9](#9-当前边界与已知缺口) 中的已知缺口。HyperOS 等系统首次侧载需额外开启“USB 安装 / USB 调试（安全设置）”。

**为什么不用 Root**：题目允许 Root/系统签名/改 ROM，但要求说明普通用户如何落地。Root 路线能扩大能力面，却把安装成本和风险转嫁给用户，且不能替代界面操作能力；如果后续采用，会在 README 和答辩中单独说明权限、风险与落地方式。

## 7. 快速开始

需要 JDK 21、Android SDK 36 / Build Tools 36.0.0 与仓库自带 Gradle wrapper（最低安装 API 33）。

```sh
# 1. 构建
./gradlew :capability:assembleDebug :app:assembleDebug

# 2. 安装
adb install -r app/build/outputs/apk/debug/app-debug.apk

# 3. 启动
adb shell am start -n agent.next.app/.MainActivity
```

4. 在设备上安装并启动 Shizuku，通过无线调试完成授权。
5. 在 AgentNext「设置与隐私 → 导入 model config」中导入模型配置（仅 HTTPS；密钥加密存储，不进入仓库）：

```json
{
  "base_url": "https://<your-endpoint>/v1",
  "model": "deepseek4.1flash1017",
  "api_key": "<YOUR_KEY>"
}
```

6. 选择起始 App，输入任务并开始。预期看到：通知栏出现运行状态；用户主屏不受影响；任务结束后给出结果报告，或在需要本人处理时出现交接通知。

模型要求：OpenAI 兼容 chat-completions、tool calling 与图片输入。当前默认模型为 **DeepSeek 4.1 Flash（`deepseek4.1flash1017`）**。

## 9. 当前边界与已知缺口

- **证据版本**：源码已冻结于 `dfa8b7e`（tag `demo-2026-10-21`）；京东录屏使用当前 reactive 循环与同一 Demo 构建（SHA-256 `c652008c…`）。夸克三次 DONE 属旧执行版本，仅作历史证据。
- **演示视频**：视频另行托管，不随仓库分发；录制时长 128.2 秒。
- **设备**：任务验收仅在 Redmi Pad Pro 平板；Pixel 4 XL（Android 13）smoke 停留在观察阶段，截帧失败，端到端未通过；单 ROM。
- **任务面**：京东购物任务只录了一次，未重复；真实支付/登录/验证码未验证（[失败记录](docs/shop-flow-attempt-2026-10-21.md)）；WebView/RN/自绘控件定位能力弱。
- **并发**：没有量化卡顿/焦点抖动数据；20 分钟 soak 只证明前台服务存活（[记录](docs/foreground-soak.md)）。
- **权限落地**：普通用户仍需手动安装并授权 Shizuku；一键化未解决。
- **运行时**：完整进程恢复与可恢复会话未实现；部分治理/重规划路径只在测试中接线。
- **核验**：独立核验覆盖仍有限；`TaskReport` 的覆盖判断需加强。

## 11. 项目结构

```text
app/          Android 任务入口、运行时、预览接管与设置
brain/        纯 JVM 规划、执行循环、动作策略、风险与核验
device-api/   纯 JVM 设备操作接口与数据契约
capability/   Shizuku 服务、私有虚拟屏、观察与定向输入
testkit/      设备布景、诊断探针、故障注入与独立核验工具
docs/         架构决策、按日期记录的验证证据与已知缺口
tools/        host 测试与构建辅助脚本
```

调用关系：`app → brain → device-api ← capability`，`brain` 不依赖 Android UI/Shizuku。

## 12. AI 辅助开发说明

本题鼓励使用 Coding Agent，也会在答辩中追问。本项目的实际做法：

- 用 Codex 辅助定位、编码、回归和**只读复核**；架构决策、风险边界和验收口径由人确定。
- 明确禁止：让模型生成固定点击序列、由电脑替代 Agent 操作业务页面、把“通过测试”写成“任务成功”。
- 关键边界先写反例再修复：中性描述不能绕过支付控件、旧节点不能复用授权、额外要求不能被只读计划合并丢弃；实机失败（连接请求被吞、后台清理过早、WebView 标题缺 CLICKABLE、过程提示被截断）都保留记录并转成回归。
- 模块测试与真机证据分开呈现；修复后按安装包重新构建并复跑，不以旧 PASS 代替新包结果。
